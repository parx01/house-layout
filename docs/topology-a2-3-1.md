# A2.3.1 topology integrity hardening

> Historical note: A2.6.1 supersedes the temporary legacy/topology equality rule documented here. Canonical topology is now authoritative; the remaining validation and V1-recovery protections are documented in `topology-a2-6-1.md`.

A2.3.1 keeps the curated A2.3 graph unchanged and hardens the temporary period
in which the rectangle editor is still the production UI.

## State transition contract

- ProjectV2 schema revision 3 uses truthful `building.status` values:
  `topologyActive` or `topologyDeferred`.
- Active topology is valid only with the known Option-3 legacy geometry and the
  exact curated topology graph. A valid but different graph is rejected while
  the legacy editor remains authoritative for edits.
- Moving, resizing, adding, or removing a legacy room; hiding a room wall;
  adding/removing a legacy line wall; or changing legacy site dimensions
  demotes topology to the existing deferred A2 slot. It is never reactivated
  implicitly if the rectangles later happen to resemble the baseline again.
- Reference visibility/opacity, snapping, label visibility, room labels,
  coverage inclusion, and the legacy common-area estimate do not describe
  physical wall geometry and therefore do not invalidate topology.
- Loading the immutable V1 baseline recognizes its room/wall geometry and
  attaches the curated graph. Edited or arbitrary V1 geometry remains deferred.
  Presentation-only differences do not prevent safe baseline recognition.

The immutable V1 recovery fixture retains its original approximate
15,000 x 24,150 mm site. When that known fixture is wrapped as ProjectV2, its
active legacy UI state is normalized to the authoritative 14,986 x 24,130 mm
property. An arbitrary V1 site's dimensions are preserved instead. This avoids
the first presentation-only save falsely appearing to be a site geometry edit.

## Cross-model validation and migration

Revision-3 validation requires building status to agree with topology status.
For active topology it also requires:

- exact Option-3 legacy geometry;
- exact curated graph identities, coordinates, connectivity, and thicknesses;
- legacy and authoritative site dimensions to agree;
- every node centre and complete perpendicular wall-thickness band to remain
  inside the current property boundary.

Revision-2 projects migrate explicitly to revision 3, deriving truthful
building status from their topology. The released A2.3 baseline therefore
remains active; deferred and empty topology remain non-active. Original A1
documents without a revision continue to migrate to deferred topology.

## Diagnostic overlay

`diagnostics/option-3-topology-overlay.svg` is generated by
`npm run diagnostic:topology-overlay`. It draws translucent wall-thickness
bands, centre-lines, and all nodes over the independently preserved reference
image. `npm run diagnostic:topology-overlay:check` and automated tests prevent
the artifact from becoming stale. It is not imported by the production UI.

The A2.3.1 visual check found the canonical graph aligned with the architectural
wall lines across the rear room bank, central partitions, staircase return, and
front room bank. The open puja/lobby edge also remained correctly unclosed. No
A2.3 geometry correction was required.

Face extraction, semantic spaces, openings, coverage, and production topology
editing remain outside this pass.
